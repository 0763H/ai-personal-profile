## 0. 怎么用这份档案

### 给 AI 助手（读之前先看这里）

1. 按顺序读：`个人简介` → `沟通偏好` → `工作习惯`，这三节决定你该怎么回答我。
2. 涉及技术选型时再看 `常用工具与技术栈`；涉及「能不能做」时看 `项目经验与成果`。
3. 任何与我的要求冲突的默认行为，**以本档案为准**；档案没写的，直接问我，别猜。
4. 标注 `示例` 的条目是占位模板，不代表真实信息——遇到就跳过并向我要真实内容。
5. 需要更新的地方，请直接指出「第几节第几条」，方便我改。

### 给人（我自己）

- **只改这一个文件就能被所有 AI 读到**，不需要同步到每个客户端。
- 每次改动都走一次提交，提交信息写清楚改了哪一节（见 [变更记录](#变更记录)）。
- 待办放在 [Issues](https://github.com/0763H/ai-personal-profile/issues)，哪节还没填完就开一个 issue。

## 2. 工作与学习习惯

- **节奏：**（示例）上午做需要专注的深度工作，下午处理沟通与杂事。
- **拆解方式：**（示例）先要一个能跑的最小版本，再迭代；讨厌一上来就做完整设计。
- **验证偏好：**（示例）结论必须有可复现的命令或数据支撑，不接受「应该可以」。
- **学习路径：**（示例）先看官方文档和最小示例，再读源码；视频教程优先级最低。
- **卡住时：**（示例）卡超过 30 分钟就先记录问题、换个任务，回来再攻。
- **环境：**（示例）Windows 主力机，命令行用 PowerShell 7。

> 💡 填写建议：写「你实际怎么做」，不写「你认为应该怎么做」。AI 会照这个调整工作方式。

## 3. 沟通风格偏好

| 维度 | 我的偏好 | 反面例子（别这样） |
| --- | --- | --- |
| 详略 | （示例）先给结论和可执行步骤，细节折叠在下面 | 铺垫三段才说重点 |
| 语气 | （示例）直接、平实，不用客套和表情堆砌 | 「非常抱歉打扰您……」 |
| 不确定时 | （示例）明说「不确定」并给出验证方法 | 编一个看起来合理的答案 |
| 追问 | （示例）缺关键信息时一次问清，别边猜边做 | 猜错方向后返工 |
| 代码 | （示例）给可运行的最小片段 + 关键行注释 | 大段伪代码 |
| 纠错 | （示例）直接指出我哪里错了，别顺着我说 | 一味附和 |

> 💡 填写建议：这一节最影响体验，值得写细。把「你最烦的回答方式」也写进去，比正面描述更有效。
